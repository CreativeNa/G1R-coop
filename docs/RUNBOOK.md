# Runbook: как прогнать проверки самому

Короткая шпаргалка: что запускать на живой паре, что при этом должно быть открыто и куда смотреть. Все результаты
пишутся в `docs/reports/`, выводы — в `docs/TESTLOG.md`.

## Что должно быть запущено

| Что | Как |
|---|---|
| игра на обоих ПК | `CoopLauncher.ps1` (он же поднимает `blackbox` и `diag link serve`) |
| мост на госте | его запускает лаунчер гостя; без него все проверки с `-Peer` покажут `SKIP` |
| адрес гостя | Radmin `x.x.x.x`, порт моста TCP 40004 |

## Инварианты (10 секунд, ничего не меняет)

```powershell
.\tools\cooptest.ps1 -Peer x.x.x.x
```

Смотрит обе копии: сборки по содержимому, исключения, роли (в том числе по заголовку окна), контакт, `missing`
(«не растёт», а не «ноль»), стоимость кадра, медленные вызовы, гигиену лога. Отчёт — `docs/reports/online_<штамп>.md`,
exit code 1 при любом FAIL.

Всё сразу — инварианты, аудит загрузок и рост лога — одной командой (около минуты, ничего не меняет):

```powershell
.\tools\check_online.ps1 -Peer x.x.x.x              # замер роста лога за 1 минуту
.\tools\check_online.ps1 -Peer x.x.x.x -Minutes 5
```

Рост лога — регрессионный гейт: до переноса диагностики `npc` за файл это было 13 МБ/час, сейчас ~0,5.

Офлайн, без игры:

```powershell
.\tools\cooptest.ps1 -Mode Check -GuestReport native\build\guest_report_<штамп>.json
```

## Сценарии (нужны действия игроков)

```powershell
.\tools\cooptest.ps1 -Mode List                                  # что есть
.\tools\cooptest.ps1 -Mode Run -Only trade -Peer x.x.x.x     # интерактивно: скажет, что делать
.\tools\cooptest.ps1 -Mode Run -Only npc,clock -Auto -Peer ...   # без нажатий: ждёт и проверяет сам
```

| Сценарий | Что нужно сделать |
|---|---|
| `npc` | просто постоять рядом со стражей 30 с |
| `clock` | ничего, если время ставить через `cheat_time_h.txt` |
| `items` | гость подбирает предмет |
| `chest` | гость открывает сундук и кладёт вещь, хост подходит |
| `trade` | хост открывает Мордрага и покупает одну вещь |
| `trade_buyout` | гость выкупает стопку целиком |
| `reconnect` | `net_sim.txt` с `loss=100` на 20 с, потом удалить |
| `reload_busy` | F9 у хоста при открытой торговле у гостя (теряет прогресс с сейва) |
| `pickup_both` | оба жмут подбор одного предмета |
| `soak` | 10 минут обычной игры |

## Эмуляция сети

Файл `%LOCALAPPDATA%\G1RCoop\app\net_sim.txt`, читается каждые 2 с, действует только на **исходящие** пакеты этой
копии (мост умеет заливать только модули, поэтому «симметрично» не получится):

```
loss=100                 # полный обрыв
delay=150 jitter=40      # задержка
loss=30 delay=100        # потери + задержка
```

Удалить файл — сеть снова идеальная. Не забыть удалить: с ним игра так и останется с потерями.

## Автоматические проверки без игрока

```powershell
.\tools\run_auto_tests.ps1                        # всё, что доступно прямо сейчас (~5 с без игры)
.\tools\run_auto_tests.ps1 -Peer x.x.x.x      # плюс инварианты и поиск дублей на паре
```

Что внутри:

| Инструмент | Что проверяет | Нужна игра | Время |
|---|---|---|---|
| `test_savesync_security.ps1` | корректный токен переносит сохранения; неверный и отсутствующий отклоняются; **имя вида `..\..\pwn.sav` не пишется на диск**; объявленный размер 4 ГБ не подвешивает клиента; мусорная метка времени не роняет его | нет | ~5 с |
| `cooptest.ps1 -Mode Check` | инварианты по двум копиям | да, оба ПК | ~10 с |
| `fuzz_net.ps1` | 200 битых UDP-пакетов на порт 40001: пустой, 1 байт, правдоподобный заголовок с мусором, 8 КБ, 60 КБ — копия должна выжить и не дать новых `EXCEPTION` | да | ~5 с |
| `test_install_cycle.ps1` | раскладка пакета и все файлы против `manifest.json`; с `-AllowSideEffects` — реальная установка/удаление в песочнице (`LOCALAPPDATA` подменяется) | нет (кроме цикла) | ~1 с |
| `test_load_loop.ps1` | N нажатий F9: каждая загрузка ровно одна, интерфейс жив; требует `-IUnderstand` | да | ~30 с на загрузку |
| `test_languages.ps1` | смена `m_DisplayLanguage` с бэкапом, `-Restore`, `-Shot` (скриншот окна) | для скриншота | ~1 с || `find_duplicates.ps1` | одно и то же событие пришло на **обе** копии в окне N секунд — так выглядит известный баг «NPC-скрипт срабатывает дважды» | да, оба ПК | ~10 с |

`find_duplicates` — искатель, а не приговор: часть событий законно применяется на обеих копиях (состояние квестов,
слова истории). Он показывает кандидатов и отдельно считает повторы внутри одной копии (это работа ack-системы).

## Долгий прогон

```powershell
.\tools\blackbox.ps1 -Interval 30 -NoProbe -Peer x.x.x.x -GuestEvery 10
```

`-NoProbe` обязателен на паре «два ПК»: шаг паритета стучится в probe гостя и без этого виснет. `-Peer` включает
наблюдение за второй копией: раз в `-GuestEvery` сэмплов (по умолчанию 10, то есть раз в 5 минут) рекордер тянет
отчёт гостя и пишет его fps, память, `missing` и исключения в ту же строку jsonl. Рекордер сам пишет
`blackbox_report_*.md` при первой аномалии (обрыв, тишина в логе, fps ниже 15, новые `EXCEPTION`).

## Выкат правки и проверка

```powershell
.\tools\deploy.ps1 -Module story -Peer x.x.x.x
```

Собирает, копирует локально, заливает гостю, ждёт 12 с и сравнивает **содержимое** выкаченных модулей (sha256) с
отчётом гостя. Строка `S versions: this build is ...` печатается как справка: она пишется только при загрузке
модуля `story`, поэтому после выката `npc` или `pose` она законно старая.

## После каждой правки

```powershell
.\tools\load_audit.ps1        # загрузки/фаталоги по логу
.\tools\cooptest.ps1 -Peer x.x.x.x
```

## Грабли, которые уже стоили времени

* **UI-меню не реагируют на `inject`** — открыть ими можно, закрыть нельзя: Esc закрывает инвентарь, но не меню паузы
  (там нужен клик по «Продолжить», `realclickat.ps1 -X 190 -Y 391`). Игровой ввод (`inject`) не двигает героя и не
  достаёт оружие — движения и бой только руками или реальными клавишами (`realkey.ps1`).
* **Диагностика npc** включается файлом `npc_diag.txt`; без него в логе нет ни `N diag`, ни `N rig`.
* **Правка `.ps1` с кириллицей** теряет UTF-8 BOM и перестаёт парситься — после правки проверять первые три байта.
* **`trade_poll`** больше не сканирует объекты, когда пира нет; при подключённом пире сканирование осталось
  (раз в 3 с, ~27 мс) — это известный открытый пункт `docs/BUGS.md`.

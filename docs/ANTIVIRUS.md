# Антивирус: что может сработать и что делать тестеру

Проверка выполнена 2026-11-09 на Windows 11 с Microsoft Defender (защита в реальном времени, облачная защита уровня
«расширенная», PUA-защита включены, сигнатуры свежие). Сторонние антивирусы **не проверялись**, чистая машина без
наших прошлых установок — тоже (см. «Что не проверено»).

## Коротко для тестера

Если антивирус ругается или удаляет файлы мода — это **ложное срабатывание**, а не вирус. Мод внедряется в процесс
игры и ищет адреса в памяти, поэтому эвристика антивирусов видит в нём «инжектор». Ничего вредоносного мод не делает:
не выходит в интернет, кроме прямого UDP-соединения с компьютером второго игрока, и не трогает файлы игры.

**Ничего не отключайте.** Добавьте два исключения вручную — этого достаточно.

## Как добавить исключение в Defender

1. Пуск → «Безопасность Windows» → «Защита от вирусов и угроз».
2. «Управление настройками» → «Исключения» → «Добавить или удалить исключения».
3. «Добавить исключение» → **Папка** → выбрать:
   `%LOCALAPPDATA%\G1RCoop`  (полный путь: `C:\Users\<ваше имя>\AppData\Local\G1RCoop`)
4. Ещё раз «Добавить исключение» → **Файл** → выбрать:
   `%LOCALAPPDATA%\G1RCoop\app\inject.exe`
5. Готово. Перезапускать ничего не нужно, повторите установку/запуск.

Через PowerShell (от администратора) то же самое:

```powershell
Add-MpPreference -ExclusionPath "$env:LOCALAPPDATA\G1RCoop"
Add-MpPreference -ExclusionProcess "inject.exe"
```

Убрать обратно:

```powershell
Remove-MpPreference -ExclusionPath "$env:LOCALAPPDATA\G1RCoop"
Remove-MpPreference -ExclusionProcess "inject.exe"
```

## Как проверить, что файлы не удалены

В папке `%LOCALAPPDATA%\G1RCoop\app` должны быть:

```
coopdll_<число>.dll      ядро мода
inject.exe               загрузчик
modules\                 семь файлов: anim, equip, menu, npc, pose, probe, story (.dll)
```

Быстрая проверка (PowerShell):

```powershell
Get-ChildItem "$env:LOCALAPPDATA\G1RCoop\app" -Recurse -File |
  Where-Object { $_.Extension -in '.dll','.exe' } |
  Select-Object Name, Length
```

Если файла нет — его удалил антивирус; добавьте исключение и переустановите мод (запустите установщик заново).

## Почему антивирус вообще реагирует (техническая причина)

`inject.exe` (140 288 байт) содержит классический набор для внедрения в чужой процесс:

```
OpenProcess, VirtualAllocEx, WriteProcessMemory, CreateRemoteThread,
LoadLibraryA, GetProcAddress, IsDebuggerPresent
```

и **не содержит ресурсов версии** — нет `FileVersion`, `CompanyName`, `FileDescription`. Для ML-эвристики
«безымянный PE + инъекция + проверка отладчика» — это готовый портрет `Behavior:Win32/DefenseEvasion.A!ml`.
Именно `IsDebuggerPresent` в продукте не нужен и его стоит убрать.

## Что уменьшает подозрительность без обхода защиты

Это честные улучшения, а не маскировка:

1. **Ресурсы версии и манифест** у `inject.exe`: `CompanyName`, `FileDescription` («Gothic 1 Remake co-op launcher»),
   `OriginalFilename`, `FileVersion`, `ProductVersion`, манифест с `requestedExecutionLevel asInvoker`.
2. **Убрать `IsDebuggerPresent`** — он не используется по назначению и сам по себе даёт «DefenseEvasion».
3. **Не упаковывать и не обфусцировать** — уже так; сохранить.
4. **Порядок в установщике:** исключение проверяется/добавляется **до** распаковки payload, а не после
   (сейчас так и есть: `defender exclusion` пишется в `install.log` до копирования файлов).
5. **Подписывать релиз** (обычная кодовая подпись, пусть и самоподписанная для тестов) — снижает эвристику
   «неизвестный PE».

Чего делать **нельзя** и что мы не предлагаем: обфускация, упаковка, «тихие» вызовы API, отключение телеметрии
антивируса, попытки обойти сканер.

## Что не проверено

- **Сторонние антивирусы** (Kaspersky, ESET, Avast, Dr.Web и др.) — не проверялись вообще.
- **Полностью чистая машина** (новый пользователь Windows, без наших прошлых установок и без исключений) —
  проверка шла на машине, где исключение пришлось снять вручную.
- **Повторяемость исторического срабатывания** `Behavior:Win32/DefenseEvasion.A!ml`: при сегодняшнем прогоне оно
  не воспроизвелось, хотя файл `inject.exe` побайтово тот же. Значит вердикт зависит от версии ML-модели и контекста
  запуска; гарантировать «не сработает» нельзя.
- **Карантин во время обновления** мода (файл занят игрой) — не проверялся.

## Если антивирус всё-таки удалил файл

1. Добавьте исключения (раздел выше).
2. Переустановите мод установщиком из того же пакета.
3. Пришлите отчёт: имя угрозы, имя файла, версия антивируса — по ним готовится обращение в Microsoft
   (заготовка лежит в `docs/MS_FALSE_POSITIVE_SUBMISSION.md`).

## Как проверить, что внутри `inject.exe`

Исходники открыты и лежат в репозитории — ничего скрытого в бинарнике нет:

| Что | Где |
|---|---|
| исходник загрузчика (23 строки: `OpenProcess` → `VirtualAllocEx` → `WriteProcessMemory` → `CreateRemoteThread(LoadLibraryA)`) | `native/inject.c` |
| ресурс версии | `native/inject.rc` |
| манифест `asInvoker` | `native/inject.manifest` |
| сборка | `native/build.bat` (MSVC, `/O2 /W3`) |

Собрать самому и сравнить SHA-256 — самый честный способ: собранный из этих файлов файл должен совпасть с хешем из таблицы выше (сборка детерминированная).
Лицензия мода — MIT, поэтому и читать, и пересобирать можно свободно.

Чего в загрузчике **нет**: сетевого кода, чтения паролей, работы с файлами игры, обхода защиты. Он умеет только одно —
загрузить указанную DLL в указанный процесс и напечатать адрес загруженной библиотеки.

Подробнее о детерминированной сборке и сверке хешей: docs/RELEASE_INTEGRITY.md.
